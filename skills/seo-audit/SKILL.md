# SEO audit

Optimize for business impact and evidence. Not a generic checklist.

## Inputs

Ask only for what changes the audit:

- URL
- Business / audience / primary conversion
- Target keywords or topics, if known
- Competitors, if known
- Scope: page, section, full site, technical, content, local, competitive
- Access: public web only vs analytics / Search Console / crawl exports

If the user gives only a URL, do a public audit and mark anything that needs private data as **needs verification**.

## Workflow

1. Clarify scope. If ambiguous and low-risk, assume a lightweight public audit.
2. Collect evidence from the page, SERPs, and any provided exports. Do not invent traffic, impressions, backlinks, CWV, index coverage, or rankings.
3. Analyze in layers: business fit, search intent, technical SEO, on-page, content quality, internal linking, conversion/UX, competitive gaps.
4. Prioritize. Prefer fewer high-leverage recommendations. Flag quick wins.
5. Produce the default output unless the user asked for another deliverable.

## Default output

- Overall assessment
- Primary opportunity
- Biggest risk
- Confidence: High / Medium / Low

### Detailed findings

Group under technical, intent and keywords, content, metadata, internal linking, UX/conversion, competitive opportunities.

For each finding: issue, why it matters, evidence, recommendation, example fix when useful.

### Quick wins

3–7 changes.

### 30-day action plan

Week 1 through Week 4.

Optional 1–5 scores for technical, intent, content, on-page, linking, conversion, competitive strength. Skip scoring on exploratory audits.

## Content refresh brief

When a page needs a rewrite, include target topic, intent, angle, missing subtopics, H2/H3 outline, internal links, proof points, media, and CTA.

## Style

- Be specific. "Improve content quality" is incomplete without the exact additions.
- Distinguish confirmed issues from hypotheses.
- Local sites: GBP, NAP, local landers, reviews.
- Ecommerce: faceted nav, category copy, product schema, duplication.
- SaaS: comparison, alternatives, use-case, feature, demo CTA.

## Quality bar

The user should leave knowing what is holding the page back, what to fix first, why, how, and what still needs data.
